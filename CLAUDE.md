# Image Builder — Executive Summary Visuals

This project generates publication-ready visual assets for Innovera investment memos. Two visuals are central to the Executive Summary output: the **Risk Matrix** and the **Strategic Fit vs Scalability** chart.

Both visuals are 2×2 matrix-style charts rendered as React SVG components and exported as images. They are designed to help clients quickly consume complex analysis without reading the full document.

---

## 1. Risk Matrix

**Component:** `RiskMatrixVisual` (`src/components/visuals/RiskMatrixVisual.tsx`)
**Data type:** `RiskMatrixData` (`src/lib/visual-types.ts`)
**Visual type key:** `risk_matrix`

### Purpose

Plots identified risks on a grid where:
- **X-axis** = Severity of Risk (Low → High, left to right)
- **Y-axis** = Likelihood / Probability of Risk (Low → High, bottom to top)

High-likelihood, high-severity risks appear in the **top-right** corner (red zone). This gives the reader an instant view of where attention is needed.

### How it works

The component renders a 3×3 grid (Low / Medium / High on each axis). Each risk is placed as a numbered pip in the appropriate cell. A legend below the grid maps each number to its risk label. Cells are colour-coded by combined severity:

| Zone | Colour | Meaning |
|------|--------|---------|
| High–High | Red tint | Critical — requires immediate action |
| High–Medium, Medium–High | Orange tint | Significant — needs a mitigation plan |
| Medium–Medium | Amber tint | Moderate — monitor actively |
| Low combinations | Green tint | Manageable — standard oversight |

### Data contract

```jsonc
{
  "risks": [
    {
      "id": "1",                    // display label inside the pip
      "label": "No commercial validation exists",  // legend text (max 40 chars)
      "probability": "High",        // "Low" | "Medium" | "High"
      "severity": "High"            // "Low" | "Medium" | "High"
    }
  ]
}
```

### Where it appears

- **Executive Summary** → Risks and Next Steps section (top risks aggregated from all chapters)
- **Opportunity Validation** → Risks and Next Steps
- **Market Research** → Risks and Next Steps
- **Competitive Analysis** → Risk & Fragility

## 2. Strategic Fit vs Scalability

**Component:** `TwoByTwoVisual` (`src/components/visuals/TwoByTwoVisual.tsx`)
**Data type:** `TwoByTwoData` (`src/lib/visual-types.ts`)
**Visual type key:** `two_by_two`

### Purpose

Scores the business opportunity on two dimensions and plots the result on a 2×2 matrix:

- **X-axis** = **Strategic Fit** — How well the opportunity aligns with the client's existing capabilities, market position, technology stack, and strategic priorities.
- **Y-axis** = **Scalability** — How easily the business model can grow: unit economics, market size ceiling, operational leverage, geographic expandability.

Both axes are scored 0–10 (mapped to 0–100 in the data for positioning precision). The quadrant the opportunity lands in tells the story:

| Quadrant | Position | Interpretation |
|----------|----------|---------------|
| **Top-Right** | High Fit, High Scalability | **Ideal** — strong alignment and clear growth path. Proceed. |
| **Top-Left** | Low Fit, High Scalability | **Pivot candidate** — scalable model but requires strategic repositioning. |
| **Bottom-Right** | High Fit, Low Scalability | **Niche play** — good alignment but limited growth ceiling. Evaluate ROI carefully. |
| **Bottom-Left** | Low Fit, Low Scalability | **Pass** — poor alignment and constrained growth. Redirect resources. |

### Context

This visual replaces the 6Ts framework in the Executive Summary (per team direction). It was introduced based on the observation that clients struggle to consume complex documents and need a single, intuitive chart that captures strategic alignment alongside growth potential. The scoring mechanism was proposed by Nobu and validated through experiments on the Innovera platform.

**Known issue to address:** Score consistency across sections. Experiments showed that Strategic Fit and Scalability scores can vary between Executive Summary, Full Summary, and 6-T Analysis when generated by different agents or even within the same agent. The upstream generation tool must produce scores from a single, deterministic scoring pass to avoid contradictions. See `INPUT_SPEC.md` for recommended input structure.

### Data contract

```jsonc
{
  "xAxis": {
    "label": "Strategic Fit",
    "lowLabel": "Weak Fit",
    "highLabel": "Strong Fit"
  },
  "yAxis": {
    "label": "Scalability",
    "lowLabel": "Constrained",
    "highLabel": "Highly Scalable"
  },
  "items": [
    {
      "label": "OpportunityName",   // short label shown below the dot
      "x": 70,                      // 0–100 (maps from 0–10 score)
      "y": 30,                      // 0–100 (maps from 0–10 score)
      "size": 20,                   // optional, bubble radius in px
      "color": "#2563eb"            // optional, defaults to palette
    }
  ],
  "quadrantLabels": {
    "topLeft": "Pivot Candidate",
    "topRight": "Ideal",
    "bottomLeft": "Pass",
    "bottomRight": "Niche Play"
  }
}
```

Multiple items can be plotted on the same grid to compare scenarios, sub-opportunities, or alternative business models (as recommended by Nobu for the Full Summary).

### Where it appears

- **Executive Summary** → Strategic Fit section (replaces 6Ts)
- **Full Summary** → alongside Alternative Business Model recommendations (multiple items plotted for comparison)

## Integration with Extraction Pipeline

Both visuals are extracted from chapter text via the LLM extraction pipeline defined in `src/lib/extraction-prompt.ts` and `src/lib/visual-prompts.ts`. The extraction prompt includes schemas for both `risk_matrix` and `two_by_two` types.

The chapter-specific extraction rules in `CHAPTER_EXTRACTION_RULES` and `CHAPTER_VISUAL_RULES` specify when each visual should be generated:

- `risk_matrix` is expected for every chapter's Risks section
- `two_by_two` (Strategic Fit vs Scalability) is expected in Executive Summary and optionally in Competitive Analysis

### Rendering flow

1. Upstream tool generates chapter text with embedded data
2. Extraction prompt (`VISUAL_EXTRACTION_PROMPT`) pulls structured `VisualSpec[]` from the text
3. `VisualRenderer` dispatches each spec to the correct component
4. Components render as React SVG → captured as image via `render-visual` API route
